# Development Instructions for AI Agents - Desafio Fullstack

> Guidelines for AI-assisted full-stack development of the mentor management system.

## 🎯 Project Overview

- **Purpose**: Mentor management system with full CRUD operations
- **Type**: Full-stack web application (Frontend + Backend + Database)
- **Tech Stack**: Node.js/Express backend, Vue/React/Angular frontend, PostgreSQL
- **Build**: npm/yarn with separate scripts for frontend and backend

---

## 🏗 Architecture Pattern

**3-Tier Architecture**:
- **Presentation Tier**: Vue/React/Angular UI with forms and tables
- **Business Logic Tier**: Express API with validation and routing
- **Data Tier**: PostgreSQL with relational schema

### Key Layers
```
Frontend
├── Pages (List, Form)
├── Components (Table, Form inputs, Modals)
└── Services (API client)

Backend (Express)
├── Routes (/mentors, /mentors/:id)
├── Controllers (CRUD operations)
├── Services (Business logic)
└── Middleware (Auth, validation)

Database (PostgreSQL)
└── Mentors table with indexes
```

---

## 📂 File Naming & Conventions

**Frontend (Vue/React/Angular)**:
- Components: PascalCase with `.vue`/`.tsx`/`.ts` suffix
- Pages: PascalCase in `pages/` or `views/`
- Services: camelCase with `Service` suffix
- Examples: `MentorList.vue`, `MentorForm.tsx`, `mentorService.ts`

**Backend (Express)**:
- Routes: `routes/mentors.js`
- Controllers: PascalCase with `Controller` suffix
- Services: PascalCase with `Service` suffix
- Middleware: camelCase function names

**Database**:
- Table: `mentors` (plural, lowercase)
- Columns: `snake_case` (created_at, updated_at)
- Indexes: `idx_table_column` pattern

---

## ✅ DO's

1. **DO** validate input on both frontend and backend
2. **DO** implement pagination and filtering on backend
3. **DO** use proper HTTP status codes (200, 201, 400, 404, 500)
4. **DO** show loading and error states in UI
5. **DO** format responses consistently (success/error envelope)

---

## ❌ DON'Ts

1. **DON'T** hardcode API URL (use environment variables)
2. **DON'T** skip server-side validation
3. **DON'T** display raw database errors to users
4. **DON'T** allow SQL injection (use parameterized queries)
5. **DON'T** hardcode business rules in UI

---

## 📋 Common Workflows

**Backend Setup**:
1. Create Express app with middleware (CORS, body parser)
2. Connect to PostgreSQL database
3. Create Mentors table schema
4. Implement routes: GET /mentors, POST /mentors, etc.
5. Add validation middleware (Joi/express-validator)
6. Test with Postman or Insomnia

**Frontend Setup** (Choose one):
1. Create React app with `create-react-app`
2. Or Vue app with `@vue/cli`
3. Or Angular app with `@angular/cli`
4. Install HTTP client (axios/fetch)
5. Create mentor service for API calls
6. Build pages: MentorList, MentorForm

**Implementing CRUD Operations**:
1. **Create**: POST /api/mentors with form validation
2. **Read**: GET /api/mentors with pagination
3. **Update**: PUT /api/mentors/:id with validation
4. **Delete**: DELETE /api/mentors/:id with confirmation

**Pagination & Filtering**:
1. Backend accepts `page` and `limit` query params
2. Calculate `OFFSET = (page - 1) * limit`
3. Use `LIMIT ?` and `OFFSET ?` in SQL
4. Return total count for page calculation
5. Frontend displays page controls and line selector

**Form Validation**:
1. Frontend: Real-time validation (onChange)
2. Backend: Validate all fields before DB insert
3. Check required fields, formats, uniqueness
4. Return validation errors to frontend
5. Display validation messages to user
